# Battle City — C Port

[🇷🇺 Русская версия](README.ru.md)

A port of the original **Battle City** (NES, 1985) to C. Source code is a precise translation of the disassembly from [romhack/battle-city-disassembly](https://github.com/romhack/battle-city-disassembly). Every function, branch, and side effect is verified against the original ASM.

## Build

```bash
cmake -B build -S .
cmake --build build
```

Dependencies: **SDL2** (library + headers).

## Run

```bash
./build/battle_city
```

### Command-line options

| Option | Description |
|---|---|
| `--region ntsc` | NTSC timing (default). CPU 1.789 MHz, 60 FPS |
| `--region pal` | PAL timing. CPU 1.662 MHz, 50 FPS |
| `--apu-filters` | Enable NES hardware filter chain: HPF 90 Hz → HPF 440 Hz → LPF 14 kHz. Without flag — simple DC-removal HPF (~28 Hz) |

Example:
```bash
./build/battle_city --region pal --apu-filters
```

## CHR Data

Tiles (CHR) are embedded into the binary at build time (CMake `file(READ ... HEX)`) — the game runs without external files.

Alternatively, CHR can be loaded from disk files. Two formats are supported:

| File | Description |
|---|---|
| `data/chr.bin` | Binary CHR-ROM (16 KB). Must be extracted from the original ROM yourself (e.g., via `dd` or a NES emulator) |
| `data/chr.bmp` | BMP image 128×256 (512 tiles 8×8), 8-bit grayscale. Top 128×128 — sprite bank (tiles 0–255), bottom 128×128 — background bank (tiles 256–511). Each pixel is converted to NES 2bpp by intensity |

Load order: `chr.bin` → `chr.bmp` → embedded BMP.

### Architecture

- **`game/`** — platform-independent game logic. Direct ASM port preserving label structure, `goto` for branches and fallthrough.
- **`nes/`** — NES chip emulation: APU (audio), PPU (graphics), region-dependent parameters.
- **`sdl_init.c` / `sdl_run.c`** — SDL2 layer: window, audio device, semaphores, controller polling, main loop.
- APU and PPU communicate with `game/` via direct calls (`apu_write`, `ppu_data_write`), no callback registration.
- APU uses a lock-free ring buffer (SPSC) to pass register writes from the game thread to the audio callback.

### APU and PPU Register Writes

**APU** — lock-free SPSC ring buffer. The game thread calls `apu_write(reg, value)`, `apu_write_status(value)`, `apu_write_frame(value)` — data is pushed into the ring buffer (`ring_push`) with `atomic_store` (release). The audio callback (`audio_callback`) is the sole consumer: loads events via `atomic_load` (acquire) and applies them to channel state. No blocking in the hot path.

**PPU** — direct calls. `ppu_data_write(addr, val)` writes to emulated VRAM (16 KB) with nametable mirroring ($2000–$2FFF) and palette rules ($3F00–$3FFF). The screen is updated via `Screen_Buffer`: the game fills it with `(addr_hi, addr_lo, val...)` tuples, `update_screen()` in NMI parses the buffer and calls `ppu_data_write` for each entry.

### NMI and VBlank

On a real NES, the NMI interrupt is generated by the PPU at the start of vblank. In this port, it is emulated via **two threads and semaphores**:

- **Game thread** (`nes_thread`) — runs game logic. When `nmi_wait()` is called, it sets the atomic flag `game_in_nmi_wait = 1` and blocks on the `wake_sem` semaphore.
- **Render thread** (`sdl_run`) — runs in a fixed-FPS loop (60 NTSC / 50 PAL). Each frame:
  1. Sets the vblank flag in the PPU and posts `vblank_sem` (for those waiting via `vblank_wait()`).
  2. If `game_in_nmi_wait == 1` — renders the frame (`ppu_render` → SDL present), calls `nmi()`, then posts `wake_sem` — the game thread unblocks.
  3. If `game_in_nmi_wait == 0` — just updates the screen and calls `play_sound()`.

Thus, `nmi()` is called **strictly in the render thread** once per frame, and the game thread synchronizes with it via a pair of semaphores (`wake_sem` / `vblank_sem`). `plat_running` and `game_exit_buf` (longjmp) ensure clean exit when the window is closed.
